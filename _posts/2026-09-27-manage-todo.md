TODOリストについて考えるとき、私たちは「忘れないために書く」と考えがちだ。しかしいろいろな手法を調査する中で、実際には逆の目的、つまり「忘れるために書く」というパターンもあることに気がついた。

この2パターンについて、「記憶」の問題と「注意」の問題を分けて考える必要がある。

「記憶」の問題に対しては、記憶を外部化し脳の中からその事柄を追い出してしまい、「忘却」してもまた引き出せるようにする必要がある。「注意」の問題に対しては、今何をすべきかに「集中」し、そのことだけを深く考える必要がある。

忘却は記憶を外部化する。一方、集中は注意の対象を絞る。この2つは似ているようで、実は逆方向の操作である。

本記事では、これらの手法を「忘却」と「集中」という2つの観点から捉え直し、自分なりのTODO管理方法を紹介したい。

## 他手法の研究

TODOリストをどう管理するかについて、GTDやIvy Leeメソッドなど、これまでにも数多くの方法が提案されてきた。

例えばGTDシステムでは、下記のような手順が紹介されている。

> 1. Capture	捕捉する	頭の中にある「気になること」を全部外に出す
> 2. Clarify	明確にする	それは何か、行動が必要かを判断する
> 3. Organize	整理する	適切な場所・リストに振り分ける
> 4. Reflect	振り返る	定期的に見直し、最新の状態に保つ
> 5. Engage	取り組む	今やるべきことを選んで実行する

2000年代にはこのような方法論を筆頭にアナログ手法がいくつも存在した。しかし、スマートフォンの登場により、大部分のアナログテクニックが失われているように感じる。実際、テクニックを紹介するブログサイトもかなりの部分が消滅している。

これらを調べて実際に使ってみた結果、私はTODOリストにはそもそも2つの異なる目的があるのではないかと考えるようになった。

**忘却するためのリストと、集中するためのリストである。**

### 忘却するためのリスト

例えば仕事にとりかかろうとして「おっと、仕事帰りに晩御飯を買わなくちゃいけない」「Amazonの配達を頼まなくちゃ」「週末の旅行の予約を取らないと」とプライベートのことがいつまで経っても頭に湧いてくることがある。

あるいは仕事においても「Slackで依頼がきた。みておかないと」「休暇申請しておかないと」「明日のリリース作業の準備をしなくちゃ」など、今やらなくてもいいリストがずっと頭の中を支配していることもよくあるだろう。

これをすべて書き出し、「今は忘れてもいい状態」をつくるのだ。

このとき書き出したリストを「忘却するためのリスト」（以降忘却リスト）と呼ぶことにしよう。

プライベートのリストはLINEに書き込むなどして実践している方も多いかもしれない。しかし、むしろ大事なのは仕事のリストだ。仕事のことを考えているようで実は「今」に集中できていないことは往々にしてある。

こういったときにこのリストは優れた外部記憶装置となる。タスクを脳内メモリから追い出せるのだ。

### 集中するためのリスト

今やっていることのロードマップを書き出し、達成可能なTODOリストを作ろう。こちらは次に取る行動を迷わない程度まで具体化すると良い。このリストを消化するだけで、今のタスクを終えることができる。これを「集中するためのリスト」（以降「集中リスト」）と呼ぼう。

実際のリストは下記のようになる。表現は粗くても構わない。多くても3つくらいに絞るのがコツだ。

``` markdown
- 指摘された不具合を直す
    - [ ] 1/2
    - [ ] 2/2
- [ ] PRのスクリーンショットを修正する
```

私はこのリストをポモドーロテクニックと併用している。そのため、タイマーで作業を中断したときには、必ず作業のスナップショットとして使えるよう、リストを更新してから5分のインターバルに入る。セーブポイントをつくるイメージだ。

そして重要なのは、当日しか保持しないということだ。意図的に短命なリストにするために当日中に**全て消してしまおう**。あくまで「今何に集中するか」のみを書くべきである。このリストが大きくなると、「今自分は何をしてるんだっけ」と現時点を見失ってしまうからだ。

## 記憶と注意は違う

この2つのリストは形式こそ似ているが、目的も中身も全く異なるものである。

忘却リストは積極的に記憶から外し、データを外部化することを目指す。そのため、リストは巨大でかまわないが、できれば整理されていることが望ましい。数日後の自分が読んでも理解できるようにしておかなければならない。

一方で集中リストは「今何をしているか」の一点にフォーカスしたものだ。自分に内在する意識をより鮮明にするためのものである。工夫の仕方によってはアナログで書き出すのもいいだろう。そのため、長期的に保存しなくても構わないし、完了後、あるいは日をまたいだら削除が基本だ。

忘却リストは「何を覚えておく必要がないか」を決める。集中リストは「何に注意を向けるか」を決めるものなのだ。

## 具体的な運用

私はこれをObsidianで管理している。具体的なTODOリストの中身は以下のようになっている。

``` markdown
# 忘却リスト
- [ ] 報告書
  - [x] [ここ](https://wiki/aaa) に雛形作った
- [ ] PR#1223実装
- [ ] 有給申請

## レビュー
- [ ] fooさんから [PR](https://github.com/pr/1211)
- [ ] barさんから [PR](https://github.com/pr/1212)
  
## 依頼
- [ ] Aさんから調査依頼 [Slack](https://slack.com/123)

# 集中リスト
- PR#1223 [PR](https://github.com/pr/1233)
  - [x] ローカルを最新化
  - [ ] ブランチを切る   
  - [ ] スクショ確認
```

ポイントをいくつか挙げよう。

### 忘却リストのみ前日から引き継ぐ

私はそのTODOファイルを毎朝新規作成し、「忘却リスト」の中身を整理している。未完了のものをコピペするのだ（実際にはAIツール化している）。

定期的に優先度や締切からリストの中身を精査しつつ、更新していく。スクラム開発でいえばバックログに相当すると考えればアイデアとしては大きくは違わない。

一方で「集中リスト」はその日限りのリストだ。日付を新しくしたファイルを作った朝はかならず集中リストは空っぽである。完了すればチェックするが、大項目であればどんどん削除していく。

そうすることでリスト自体の完成度ではなく、今何に集中するべきかの極めて単一の目標にフォーカスしたロードマップとして運用できる。

当日終わらなければ忘却リスト側に移行してもいいだろう。

### リンクを付す

必ずパーマリンクを付すこと。これによってタスクの中身を思い出す時間を最大限に短縮できる。
たとえ忘却リストに入って何日も経ったタスクであっても、そのチケットへのURLやチャットのURL、申請ファイルの下書きへのURLがあれば必ず思い出すだろう。

### 依頼は忘却リストに放り込む

Slackやメールなどの依頼は忘却リストに放り込もう。この操作はGTDのInboxに相当する。作業中であれば、次に時間が空くまで忘却リストに入れておくことで、コンテキストスイッチを減らせる。Slackで依頼が飛んでくるたびに真剣に噛み砕いていては、認知負荷が高まる一方で目の前の仕事は終わらない。一旦未来の自分にタスクを渡してしまうのだ。

## なぜ今これが必要か

最近あまり議論されなくなったTODOリスト管理だが、近年重要性が増しているように感じる。理由はAIだ。

AIによって、我々は1つの仕事を深く掘るだけでなく、コード、調査、文章、コミュニケーションなど複数のコンテキストを高速に行き来するようになった。AIは個々の作業の速度を上げる一方、**人間が保持すべきコンテキストの数まで減らしてくれるわけではない**。この増大したコンテキストを人間の頭の中だけで保持するのは難しく、外部化する仕組みの重要性はむしろ増している。

TODOリスト管理は、すでに優れた手法がいくつも提案されている。

しかも具体的な実践つきだ。日本人は文房具が大好きなので、こういったTODO管理用のアナログツールや文房具の類にも枚挙の暇がない。さらに、スマートフォンアプリでは開発初心者の定番題材であることから、とんでもない数のアプリケーションをマーケットで見つけられる。

しかし、これらが与えてくれるのはフォーマットにすぎない。これらがどれだけ便利さをうたっていたとしても、使う側が本質を捉えなければ、TODOリストは単なるお買い物リストのままだ。

本稿の2本立てのTODOリスト——「忘却リスト」と「集中リスト」——は、私が多くの手法を調査し抽象度を高めた結果生まれた枠組みである。付録の過去事例を改めて見ると、それぞれこの2つの手法のどちらか、あるいは両方をシステマティックに統合したものと見ることができるだろう。

TODOリストは、すべてのタスクを一か所に並べるためのものではない。
覚えておく必要のないものを外に出し、その中から今注意を向けるものだけを取り出すためのものだ。

AIが仕事の速度を上げるほど、頭を空にする技術の価値は増す。忘却と集中、この2軸でTODOを組み直せば、リストは単なるお買い物メモではなく、思考を整える強力な装置になる。  

## 付録 他手法

リンクは原著ではなく、ネット上で参照できる二次情報をあえて参照している。

### GTD

本稿のシステムに当てはめるならば、忘却リストから集中リストへどのように移行し実践するかが書かれている。ただし、様々なユースケースに対応した結果、システムがやや巨大で、個人的には扱いづらい。
本稿にマッピングすると、1が忘却リストだ。2が集中リストへの移行、3および4は新しいファイルに移し替えるときに自動的に行える。

> 1. Capture 捕捉する 頭の中にある「気になること」を全部外に出す
> 2. Clarify 明確にする それは何か、行動が必要かを判断する
> 3. Organize 整理する 適切な場所・リストに振り分ける
> 4. Reflect 振り返る 定期的に見直し、最新の状態に保つ
> 5. Engage 取り組む 今やるべきことを選んで実行する

[Getting Things Done® - ストレスフリーの仕事術「GTD®」](https://gtd-japan.jp/)

### Moleskin PDA

プロジェクトページにはマインドマップが見られるが、これはClarifyの1つの工程と考えられる。

[私のMoleskine PDA](https://web.archive.org/web/20171027120740/http://www.aoky.net/articles/kathy_sierra/gettingstaying_.htm)

### Ivy Lee メソッド

集中リストに特化している。

> 1. 夜、紙に「明日やるべきこと」を6つメモします
> 2. その6つの項目を重要だと思う順に番号を振ります
> 3. 翌日、メモの順番に沿って仕事（勉強）を進めましょう
> 4. 全部できなかった場合は、悔やむことなく忘れましょう
> 5. その日の夜も、明日のための6項目を新しくメモします
> 6. 1〜6を毎日行ないます

[100年受け継がれている超効率化メソッド「アイビー・リー・メソッド」を試してみた。 - STUDY HACKER（スタディーハッカー）｜社会人の勉強法＆英語学習](https://studyhacker.net/ivy-lee-method)

### Bullet Journal

スケジュール、リマインダー、TODOリストを含む統合システム。TODOリストは「忘却リスト」に近い。
[初心者でも簡単！バレットジャーナルの書き方の基本](https://www.kokuyo-shop.jp/sc/u_page/column.aspx?ucpid=UC000065)

衝撃的なタイトルだが、極端な「集中型」。

### Kanban, スクラム

これらはさらに文脈が異なり、チーム内でどのように消化していくのかというものになる。自分がタスクオーナーになっているとは限らず、今回のコンテキストとは大きく異なる。
